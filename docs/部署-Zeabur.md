# 部署到 Zeabur（免费额度版）

> ⚠️ **2026-10-17 更正**：Zeabur 的 `Free` 计划现在**只包含面板功能**（管理你自己已有的服务器），
> **不再提供任何计算资源** —— 也就是说不能免费跑服务了，$5/月的 Dev 只给 14 天试用。
> 这份文档保留作参考。**要免费部署请看 [部署-Render.md](部署-Render.md)**（Render 的免费档仍在）。

> 目标：把 pitwatch 挂到公网，别人打开一个网址就能用。
> 全程约 15 分钟，不需要信用卡，不需要自己配服务器、Nginx、HTTPS 证书。

---

## 0. 先弄清会发生什么

部署完你会得到一个这样的地址：

```
https://pitwatch-xxxx.zeabur.app
```

打开就是完整系统：可以建项目、导台账、看曲线、导出日报。

**但有一点必须提前知道**：免费额度下容器**不活跃会自动休眠**（有人访问时几秒唤醒），
而且**磁盘是临时的** —— 重启 / 重新部署后 `database/` 会丢。

所以镜像里做了两件事应对：

| 机制 | 作用 |
|---|---|
| `MONITOR_DEMO_SEED=1` | 启动时发现库是空的，**自动建一个示例项目**（8 测点 / 6 期数据）。重启后自己长回来，别人随时点开都有东西看 |
| 数据目录全部指向 `/data` | 想保住数据，在 Zeabur 挂一个卷到这个目录就行，不用改代码 |

> 结论：**演示用完全够了**。真实工程数据继续留在本机，一点不外流。

---

## 1. 前置条件

仓库里已经有这几样，不用你再动手：

- `Dockerfile`（前端构建 + 后端运行，单端口 8000）
- `.dockerignore`（本机 500MB 的运行数据不会上传）
- 代码已经推到 **https://github.com/sky-Edge/pitwatch**

---

## 2. 注册 Zeabur

1. 打开 **https://zeabur.com**
2. 右上角 **Sign in** → 选 **Continue with GitHub**
3. 授权后会进入控制台（Dashboard）

不需要填信用卡。

---

## 3. 建一个项目

1. 控制台点 **Create Project**（或 New Project）
2. 起个名字，比如 `pitwatch`
3. **区域选亚洲的**：`Hong Kong` / `Tokyo` / `Singapore` 都行（免费额度只能用这几个区）
   - 你的使用者都在国内，**别选美区**，延迟会很难看

---

## 4. 部署仓库

1. 进入刚建的项目 → 点 **Add Service**（或 Deploy）
2. 选 **Git** → **Configure GitHub**（第一次会要你授权 Zeabur 读仓库）
3. 在仓库列表里选 **`sky-Edge/pitwatch`**，分支 **`master`**
4. Zeabur 会自动检测到根目录的 `Dockerfile`，直接点 **Deploy**

构建大约 3–6 分钟（要装 Node 依赖、跑 `tsc && vite build`、装 Python 依赖）。
构建日志里能看到 `npm run build` 和 `pip install` 的进度，属正常。

---

## 5. 配环境变量（一般不用改）

Dockerfile 里已经预设好了，部署后**默认就是演示模式**：

| 变量 | 值 | 说明 |
|---|---|---|
| `MONITOR_DEMO_SEED` | `1` | 空库时自动建示例项目 |
| `MONITOR_DB_URL` | `sqlite:////data/database/monitor.db` | 数据库位置 |
| `MONITOR_TEMPLATES_DIR` | `/data/templates` | 母版原件 |
| `MONITOR_UPLOAD_DIR` | `/data/uploads` | 导入的台账 |
| `TZ` | `Asia/Shanghai` | **必须**，否则"今天"会偏 8 小时 |

要改的话：服务页 → **Variables** → 编辑。改完会自动重新部署。

> ⚠️ 别把 `MONITOR_DEMO_SEED` 设成 `0`，否则空库时别人点开是空列表。

---

## 6. 生成访问域名

1. 服务页 → **Networking**（或 Domains）
2. 点 **Generate Domain** / **Add Domain**
3. 会得到一个 `xxx.zeabur.app` 的地址，HTTPS 自动配好

打开它，应该看到项目列表里已经有一个 **「示例项目（8 个测点 · 6 期演示数据）」**。

---

## 7. 上线自检（照着点一遍）

| 检查 | 期望 |
|---|---|
| 打开首页 | 看到项目列表，里面有 1 个示例项目 |
| 点进项目 → 曲线 | 有折线，不是空白 |
| 成果导出 → 选一期 → 导出 Excel | 能下载到 .xlsx |
| 预警事件 | 有预警/报警条目（演示数据本身就是带预警的）|
| 刷新页面 | 一切正常（不是 404）|

如果首页是空白页：多半是前端没构建成功，去看构建日志里 `vite build` 那一段。

---

## 8. 关于数据能不能留住

**如果只是给人看**：什么都不用做。重启后靠 `MONITOR_DEMO_SEED` 自动重建示例数据。

**如果要让数据长期留存**（比如真拿来给同事用）：

1. 服务页 → **Volumes**（存储）→ 新建卷
2. **挂载路径填 `/data`**（一定是这个，容器里所有数据都在它下面）
3. 免费额度是否支持卷、怎么计费，**以控制台当时的显示为准**
4. 挂好之后重新部署一次

挂了卷之后，`MONITOR_DEMO_SEED` 也不会重复建项目 —— 它只在"库是空的"时才动手。

---

## 9. 以后怎么更新

代码推上去就自动部署，不用再点任何按钮：

```bash
git push origin master
```

Zeabur 收到 webhook 后自动重建。想手动触发：服务页 → **Redeploy**。

## 10. 费用与限额（免费额度）

| 项 | 免费计划 |
|---|---|
| 每月额度 | 约 **$5** 计算额度，按月重置 |
| 单服务规格 | 最多 1 vCPU / 2GB 内存 |
| 区域 | 香港 / 东京 / 新加坡等亚太区 |
| 信用卡 | **不需要** |
| 超额 | 服务暂停（**数据保留**），下月额度重置后自动恢复 |
| 冷启动 | 休眠后首次访问慢几秒 |

**怎么不烧超**：
- 保持**自动休眠开启**（这是免费能长期用的关键）
- 别让它 24 小时满负载跑（例如别开着定时任务反复唤醒）
- 导出大文件耗的是流量，也在额度里

按这个系统的用量（偶尔有人打开看看），一个月通常连 $1 都用不到。

## 11. 常见问题

**Q：打开很慢，要等十几秒？**
免费计划休眠了，正在冷启动。等一会儿就好。想一直在线就升级到 `Dev` 计划（$5/月，可关休眠）。

**Q：首页 404 或白屏？**
1. 确认构建成功（Build 日志里有没有 `✓ built in`）
2. 确认服务端口是 `8000`（Dockerfile 里写死了，平台注入 `PORT` 也能兼容）
3. 打开 `/api/health` 看后端是否活着 —— 返回 JSON 就说明后端没问题

**Q：别人能随便改我的演示站吗？**
能。这个系统没有登录功能。**所以别放真实工程数据** —— 演示站就用示例数据，谁改乱了重启一下就恢复。

**Q：想加访问密码怎么办？**
系统本身没有账号体系。最简单的做法是在前面挂一层带 Basic Auth 的反向代理（Zeabur 上可以再加一个 Caddy 服务），或者把整个站设为不公开分享。要做的话说一声。

**Q：数据能在自己电脑和线上之间搬吗？**
可以。`database/monitor.db` 就是全部数据，配合导出/导入功能搬。

---

## 12. 出问题先看这三处

1. **Build 日志**：`npm run build` 或 `pip install` 有没有报错
2. **Runtime 日志**：启动后有没有 `[演示模式] 空库，已自动创建示例项目`
3. **`/api/health`**：返回 `{"status":"ok","version":"1.1.2",...}` 说明后端正常
