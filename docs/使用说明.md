# 基坑拉森钢板桩沉降与水平位移观测系统 · 使用说明（V1.3）

> 适用对象：施工现场技术员、监测人员、项目技术负责人
> 版本：V1.3（无日期补填导入 / 母版加固 / 原始数据区固定 V0） · 最后更新：2026-09-02

---

## 一、这是什么系统

把工程现场每天重复的 **观测数据录入 → 整理 → 计算 → 累计 → 异常判断 → 曲线制作 → 日报制作 → Excel 归档** 自动化。

```
录入/导入观测数据 → 自动算本次变化 → 自动算累计 → 自动算速率
   → 自动判断预警 → 生成曲线 → 逐期对比 → 导出日报(Excel/Word) → 定期备份
```

**四条铁律（系统设计核心）**：
1. 原始数据**只增不改**：填错了走「更正」，旧值永久保留、可追溯；
2. 计算可复算：同一批原始数据，任何时候重算结果一致；
3. 预警规则、正负号规则全部**可配置**（可选用国标或自定义）；
4. 数据**永不静默覆盖**：重复导入、冲突数据一律跳过并报告。

## 二、启动与停止（重要）

### 启动

**双击桌面「基坑监测系统-启动.bat」**，会弹出黑色窗口并自动完成：
1. 启动后端服务（端口 8000）
2. 启动前端页面（端口 5173）
3. 自动打开浏览器进入系统（若没自动打开，手动访问 http://127.0.0.1:5173 ）

> 首次等待约 5-10 秒属正常。窗口内会滚动显示服务日志。

### 停止

**直接关闭那个黑色窗口**（点右上角 ✕ 或按 Ctrl+C）：
- 全部服务随之停止，不会残留后台进程；
- **每次退出会自动备份一次数据库**（保存在 `database/backups/`，保留最近 30 份）。

### 故障排查

| 现象 | 处理 |
|---|---|
| 双击后窗口提示"端口被占用" | 系统可能已在运行（找任务栏/后台旧窗口），或上次异常退出残留进程。任务管理器结束残留的 python/node 进程后重试 |
| 浏览器打不开 | 等窗口内出现"系统已就绪"字样后，手动访问 http://127.0.0.1:5173 |
| 页面报"网络错误" | 黑色窗口被关了（服务已停），重新双击启动即可 |

## 三、每天的使用流程

### 第 0 步：建项目（首次使用或新基坑）

项目列表页 →「新建项目」：
- **项目编号**：如 `PRJ002`（唯一，不可重复）
- **项目名称**：如 `8号基坑`
- **地点**：工程位置/标段
- **正负号规则（可选）**：JSON 格式，如
  ```json
  {"settlement":{"positive_means":"down","desc":"正值=下沉，负值=隆起"}}
  ```

> 正负号决定"方向"语义显示（下沉/隆起、向坑内/向坑外）。不填按行业惯例：沉降正值=下沉、位移正值=向基坑内。

### 第 1 步：建测点（首次使用该基坑）

**方式 A —— 单点新建**：「测点管理」→「新建测点」：
- **编号**：如 `JJC1`（项目内唯一）
- **类型**：沉降 / 水平位移 / **沉降+位移**（同一根桩两项都测选这个）
- 建点时也可填"初始值"（不填则系统取第一次有效读数作基准 V0）

**方式 B —— 批量新建（推荐，几十个测点一次搞定）**：「测点管理」→「批量新建」：
- 从 Excel/文本**粘贴多行**，每行一个：`编号,类型[,初始值mm][,位置]`
  如 `JJC1,both,4907000,1#钢板桩`；类型支持中文（沉降/水平位移/沉降+位移）
- 点「校验并预览」→ 自动分成 **可创建 / 跳过(编号已存在) / 错误(格式非法)** 三组；
- 确认后一次创建全部有效行（重复点自动跳过并明示，绝不覆盖）。

### 第 2 步：每天录入数据（两种方式任选）

**方式 A —— Excel 一键导入（推荐，用你的报送模板文件）**
项目列表 →「Excel导入」→ 把当天填好的模板文件（如 `八号基坑（第一期）2026.7.31.xlsx`）拖进去：
- 自动识别两个数据 Sheet（竖向位移 / 水平位移），自动识别观测日期与列；
- 自动跳过封面、签字、说明等无关 Sheet；自动把读数（m）换算入库（mm）；
- **初始值文件**（只有初始值列的那种）会被识别为 V0 基准期，自动处理；
- **测点匹配（V1.1 新增）**：若 Excel 里的点号与项目测点不一致，预览页会出现「测点匹配」面板：
  - 点号写法相似（如 `JJC-01` vs `JJC1`）→ 自动给出候选，**下拉选择"映射到已有测点"** 一键对应；
  - 项目里确实没有的点号 → 选择「**自动建点**」（类型按该点数据自动推断，如只测沉降→沉降点）；
  - 不想处理的点可切换「跳过」，该点数据不导入；
  - **全程先确认再落库**，绝不静默建点或覆盖；
- **未识别观测日期（V1.3 新增）**：如果 Excel 表头没写"本次监测时间"，不会再整批卡住——
  预览页会出现黄色提示「未识别观测日期」，**选一个日期**（如该批数据的采集日）即可正常导入；不选则该批不导入；
- 随后展示三张清单：✓可导入 / ⚠冲突（当日已有，跳过不覆盖）/ ✗错误（如类型不匹配）；
- 确认无误点「确认导入」。

**方式 B —— 页面手工录入**
点「观测录入」：选日期 → 每个测点填读数（单位 **m**，沉降填"沉降读数"，位移点填 X/Y）→「保存本期」。
- 输入框**留空 = 缺测**（保存后自动标记"缺测"，不参与计算）；
- 保存后自动计算并显示每个测点的预警状态。

> 两种方式可混用。Excel 导入适合批量补历史数据，手工录入适合当天零星补测。
> 另提供「自动生成数据」按钮（观测录入页）：给日期范围即可生成规范限值内的演示/试算数据（source=generated，可一键清理，不污染真实数据）。

### 第 3 步：查看结果（全自动，无需手工算）

| 想看的 | 入口 | 内容 |
|---|---|---|
| 每个测点最新预警 | 观测录入页"预警状态"列 | 红=报警 / 黄=预警 / 绿=正常 |
| 项目整体预警 | 项目列表页 | 每行显示报警/预警数量，顶部横幅点名报警项目，点击看详情 |
| 沉降/水平位移曲线 | 「曲线图」 | 多测点累计变化曲线，报警点红标、预警点黄标，可切 X/Y 方向 |
| 逐期对比分析 | 「逐期对比」 | 每期与上一期对比：本次变化/累计/速率/方向/预警，缺测跨期自动标注 |
| 历史预警事件 | 「预警事件」 | 预警/报警事件清单，可一键"重新计算"（幂等重建） |
| 数据质量检查 | 「预警事件」页顶部 | 突变疑似（单期变化超阈值）、缺测统计——只提示不删除 |

### 第 4 步：出成果（V2 母版整卷模式，推荐）

**核心思路**：上传一份你"填得最满意"的整卷日报当**母版**，系统自动学会它哪里会变、怎么填，之后每期一键产出**一模一样的完整整卷**（封面/签字/概况/分析/预警统计/成果提交/两张数据表/T 列全保留，可直接报送）。换基坑或换模板只须再上传一份它的母版，**不用改任何代码**。

#### 4.1 注册母版（每个报送版式只做一次）

项目列表 →「成果导出」→「上传报送模板」→ 选你手头**已填好的一份整卷日报**（如 `八号基坑（第二十一期）2026.8.20.xlsx`）→ 命名保存。系统自动"学习"出整卷结构：

| 学到的变量槽 | 自动识别位置 |
|---|---|
| 封面观测日期 | 如 `封面!F16` |
| 签字期次（第 N 期） | 如 `签字!A11`（初始值=第 0 期，自动转中文期次） |
| 签字日期 | 如 `签字!E52` |
| 两张数据表的"本次/上次监测时间" | 如 `竖向位移!A3 / K3` |
| 天气格 | 如 `竖向位移!K2`（保留"天气："前缀） |
| 竖向位移 / 水平位移数据区 | 点号列、每列含义、数据起始行、X/Y 相邻行规则 |
| **「原始数据」区（V1.3）** | 竖向位移表右侧 N~S 列的点号坐标表（X/Y/Z），每期自动填**测点初始值（V0）**，日期固定为 V0 基准日，**不随期次变化** |

> 母版可**重复上传同名**（如换用更新版式）：同名自动替换，不会堆积旧记录（V1.3）。

#### 4.2 每期导出（一次操作出最新整卷）

「成果导出」→ 模板下拉选 **【自定义】你的母版** → 选**天气**（晴/多云/阴/雨…）→「导出 Excel」：

- 封面/签字日期、期次自动更新为本期；
- 两张数据表只由系统填：**初始值/上次测值/本次测值 + 累计/变化/速率全部算成数值写入**（覆盖模板公式，换机器打开不会变）；
- **「原始数据」区固定显示各测点 V0 初始坐标与基准日**（X=东坐标、Y=北坐标、Z=沉降值），本区不是每期观测值，导出任何一期都相同；
- 预警等级列自动填（与预警引擎一致，报警行红底）；
- 概况/分析/结论/成果清单等固定内容**原样保留**（系统经两期逐格比对确认它们每期不变）；
- 一次导出默认取**最近完整观测期**。

> **旧模式仍可用**：不选模板 = 内置标准日报；内置 Word 日报按钮不变。V1 的"重建版式"导出被母版模式取代后更贴近真实报送。

#### 4.3 更换版式 / 注意事项

- 换报送格式：再上传一份新母版即可，新旧模板并存于下拉中；
- **同名上传自动替换（V1.3）**：重复上传相同名称的模板会替换旧版（旧文件自动归档），下拉框不会堆积重复项；
- **模板原件缺失提示（V1.3）**：若下拉项显示"原件缺失，重新上传"（灰色不可选），说明该模板的文件丢了——删除该项后重新上传即可；
- **母版原件请勿删除**：`templates/` 目录存有上传的母版副本，它是导出的底模。

### 第 5 步：备份

- **自动**：每次关闭系统窗口自动备份（见"停止"）。
- **手动**：顶栏「数据备份」→「立即备份」；列表中可对任一备份点「还原」（还原前系统自动再做一次快照，可回退）。

## 四、规则与配置（项目级）

### 预警规则

项目列表 →「预警规则」→ 打开配置窗：
- 内置**规范预设库**：GB 50497-2019《建筑基坑工程监测技术标准》（钢板桩一/二/三级）、八号基坑实测模板（沉降 30mm/10mm·d⁻¹、位移 20mm/3mm·d⁻¹）、自定义空白；
- 选择预设即带出**控制值(预警)/报警值**两档，每档含 **累计变化限值(mm) + 变化速率限值(mm/d)**（双控，任一超标即触发）；
- 数值可直接修改，**以设计文件为准**；
- 每个项目独立配置，互不影响。

### 数据更正（填错了怎么办）

观测录入页直接改已录入的值 → 弹窗列出"原值 → 新值"→ 确认：
- 新值生效；旧值自动标记"已更正"并永久保留（可追溯）；**绝不覆盖删除**。
- 作废：整条误录可标记"作废"，不参与计算但保留。

## 五、数据安全设计（放心用）

| 规则 | 说明 |
|---|---|
| 原始数据只增不改 | 观测记录表不允许物理修改数值、不允许覆盖删除 |
| 删除保护（默认） | 有数据的项目/测点默认只能"归档/停用"，历史数据永久保留 |
| 彻底删除（V1.1） | 确需清理时可用「删除…」：输入编号二次确认，删除前**自动备份**可回退；会级联清该项目的观测/测点/模板等全部数据 |
| 重复导入保护 | 同日同测点已有记录 → 跳过并报告，绝不静默覆盖 |
| 异常不删除 | 突变、缺测只**标记提示**，需要人工核对 |
| 备份可还原 | 自动+手动双保险，还原前强制确认 + 自动快照 |

## 六、常见问题（FAQ）

**Q1：导入时报"测点不存在于本项目"？**
A：模板里的测点号需先在「测点管理」建好（系统不自动建点，防止点号错乱）。建好后重新导入即可。

**Q2：导出的 Excel 累计变化和模板里的对不上？**
A：系统按"读值差"严格计算（初始值文件=V0 基准），模板里若为手工填数可能有出入——以系统引擎计算为准，导出的数据已与逐期对比页一致。

**Q3：同一天录了两遍？**
A：第一遍保留；第二遍（无论手工还是 Excel）会被识别为冲突并跳过，可放心操作。

**Q4：某天没测（缺测）怎么办？**
A：留空保存即记为缺测。下一次观测的"本次变化"自动与最近一次有效值比较并标注间隔天数，曲线不断点。

**Q5：预警怎么取消？**
A：预警是自动判定。核实数据后若确属抄录错误 → 更正数值后自动重算，预警即消除；若规范值设得不合适 → 到「预警规则」调整后保存。

**Q6：数据都存在哪？**
A：全部在本地 SQLite 数据库 `database/monitor.db`（无需联网）。备份在 `database/backups/`。日常使用建议定期把 backups 目录拷贝到 U 盘/网盘。

## 七、技术信息（给维护人员）

- **架构**：前后端分离。React+TS+AntD+ECharts（前端） / FastAPI+SQLAlchemy 2.x（后端） / SQLite（库）
- **目录**：
  ```
  backend/    API、模型、服务、四个引擎（计算/预警/导入/报表）
  frontend/   页面
  database/   monitor.db 数据 + backups 备份
  tests/      pytest 测试（121 项全绿）
  tools/      辅助脚本（模板解析、批量导入）
  launcher.py + 启动系统.bat   一键启动
  ```
- **手工运行**（备用，正常请用桌面 bat）：
  - 后端：`python -m uvicorn backend.main:app --port 8000`
  - 前端：`cd frontend && npm run dev`
- **一键启停**：桌面「基坑监测系统-启动.bat」启动（关窗即停+自动备份）；桌面「基坑监测系统-关闭服务.bat」清理遗留服务。
- **测试**：`python -m pytest tests -q`（124 项全绿）
