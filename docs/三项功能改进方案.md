# 三项功能改进方案（V1.1）

> 范围：① 测点批量新建　② 项目初始测点 Excel 导入的名称匹配/映射　③ 观测报告导出模板选择
> 定位：每个基坑开工（首期）与每次报送高频动作的效率提升，不改变既有数据模型与引擎。
> 写法：问题场景 → 目标行为 → 具体方案（含操作流程、校验规则、界面/接口设计）→ 边界与兜底。

---

## 一、测点批量新建

### 1.1 当前问题场景

- 现状：测点管理页只有「新建测点」按钮，一次弹窗只能录入 1 个测点；
- 痛点：一个基坑往往 8~40 个测点（如 JJC1~JJC40，常是"沉降+位移"同点双测），逐个弹出填写非常繁琐；
- 且每次建点后要等接口往返，连续建 40 个点的人机交互成本高、易中途出错。

### 1.2 期望目标行为

在「测点管理」页新增**「批量新建测点」**入口：
- 一次可创建任意多个测点；
- 提供三种互补的录入方式；
- 提交前先做**整体校验并预览**（沿用"预览不落库、确认才写入"的既有导入原则），冲突/重复行明确标出、可单独剔除；
- 支持**整批全部成功**或**部分成功**两种结果反馈，杜绝半途而废的"幽灵操作"。

### 1.3 具体方案

#### 录入方式（三选一，界面内 Tab 切换）

| 方式 | 交互 | 示例 |
|---|---|---|
| A. 表格逐行录入 | 弹窗内一张可增删行的表格：每行 = 编号/类型/初始值(可选)/位置描述；点「+添加一行」 | JJC1 | both | 4907000 | 1#桩 |
| B. 多行文本粘贴 | 一个 TextArea，每行 `编号,类型[,初始值mm][,位置]`，支持从 Excel 复制粘贴后智能解析 | 见下方格式约定 |
| C. 编号批量生成 | 填前缀+起止号+类型，自动展开（JJC01~JJC20 沉降，或沉降+位移一起） | 前缀 JJC、1–20、类型=both |

**多行文本格式约定**（方式 B，兼容 Excel 粘贴）：
```
每行一个测点，字段以逗号/制表符/空格分隔：
JJC1,both,4907000,1#钢板桩
JJC2,settlement,,2#钢板桩        ← 初始值留空 = 取首期读数
LZ-01,displacement,3413055112   ← 位移点（X 分量初始值）
```
- 类型取值：`settlement`(沉降) / `displacement`(水平位移) / `both`(沉降+位移)，支持中文别名：沉降/水平/沉降位移。
- 表头行自动跳过（首行含"编号/类型"等字样则忽略）。

#### 校验规则（逐行校验，不中断整批）

| 校验项 | 规则 | 结果 |
|---|---|---|
| 编号必填 | point_no 非空、≤24 字符、字母数字横线（与既有导入白名单一致） | error 行标红 |
| 项目内唯一 | 与项目已有测点编号冲突 | conflict 行提示"已存在"，默认剔除 |
| 类型合法 | 必须是 settlement/displacement/both | error 行 |
| 初始值 | 数字或空；与测点类型匹配（位移点不要求填 X 初始值——X/Y 均以首期读数为基准） | warning 提示不阻断 |
| 批量内重复 | 同批两行同编号 | 后者标 conflict |

#### 操作流程

1. 点「批量新建测点」→ 弹窗选录入方式（Tab）；
2. 录入 → 点「校验并预览」→ 后端逐行校验返回 `valid / conflict / error` 三类清单；
3. 用户可勾选剔除某行（默认剔除 conflict，error 不可导入）；
4. 点「确认创建 N 个测点」→ 后端事务性逐条写入（全部成功 / 部分成功均返回明细，如"成功 18、跳过 2（已存在）、失败 1（编号格式非法）"）；
5. 关闭弹窗后测点列表刷新。

#### 接口设计

```
POST /projects/{project_id}/points/batch-preview   body: {lines:[...]} → {valid:[],conflict:[],error:[]}
POST /projects/{project_id}/points/batch           body: {items:[有效行]} → {created:n, skipped:[...], failed:[...]}
```

> 设计考量：batch-preview 不落库，batch 只收"用户确认后的有效行"，避免二次校验不一致；
> 单个测点的新建/编辑入口保留不变（兼容小批量）。

## 二、项目初始测点 Excel 导入：名称匹配与映射

### 2.1 当前问题场景

- 用户行为：新建项目 → 直接导入"初始值/初始点"Excel（或首期模板文件）；
- 现状：导入引擎对 Excel 数据行做**精确 point_no 匹配**，项目里没有同名测点 → 整行进 `error_rows`（"测点 X 不存在于本项目"），一行都导不进去；
- 痛点：Excel 里的点号（如 `JJC-01`、`1#`）与项目里预先建好的点（如 `JJC1`）写法不一致时**无法导入也没有纠正途径**；而对"初始点文件"用户往往本来就想**以 Excel 为准建点**，却被"必须先手工建点"卡住，流程倒挂。

### 2.2 期望目标行为

- 导入预览时对未知测点不再一棒子打死，而是给出**分级结果 + 三种出路**：
  1. **精确匹配**：Excel 点号 = 项目测点编号 → 正常导入；
  2. **智能候选匹配**：名称相似（大小写/分隔符/前后缀差异）→ 提示"Excel JJC-01 疑似 = 项目 JJC1"，用户一键确认映射后导入；
  3. **全新点号**：项目内确实不存在 → 提供「**按 Excel 自动建点**」选项（点名、类型按该行观测分量推断、初始值=V0），或用户改走"批量新建/编辑映射"；
- 全程**预览阶段解决，不落库**，用户确认映射关系后再真正导入。

### 2.3 匹配/映射规则（按优先级）

| 优先级 | 规则 | 示例 | 处理 |
|---|---|---|---|
| P1 | 点号精确相等（去空格后） | JJC1 == JJC1 | 直接匹配 |
| P2 | 规范化后相等：忽略大小写、全/半角、`-`/`_`/空格、前导零 | JJC-01 ≡ JJC01 ≡ jjc1 | 判定"疑似"，**建议自动对应**（可一键采纳） |
| P3 | 数字尾巴相等 + 前缀包含关系 | Excel `1#` vs 项目 `JJC1`（都含数字 1） | 低置信"候选"，列候选列表由用户挑 |
| P4 | 无任何相似 | `LZ-A` vs 项目 {JJC1..JJC8} | 全新点号 |

**规范化函数（建议内置并单测）**：
```
normalize(name) = name.upper().replace(全角→半角).remove('-','_',' ').lstrip('0')(仅当后随数字)
例：normalize("jjc-01") = "JJC01";  normalize("JJC1")="JJC1" → P2 命中
```

### 2.4 交互与纠错流程（导入向导新增一步）

```
Step1 上传 Excel → 解析出数据行（现状已有）
Step2 【新增】测点匹配确认区：
   ┌────────────────────────────────────────────┐
   │ 精确匹配  12 行   │  建议自动对应  3 行    │  全新点号 5 行  │
   ├────────────────────────────────────────────┤
   │ 疑似对应（可一键"全部采纳"或逐行改选）：        │
   │   Excel JJC-01 ────匹配──▶ 项目 JJC1  [✓]  │
   │   Excel JJC-02 ────匹配──▶ 项目 JJC2  [✓]  │
   ├────────────────────────────────────────────┤
   │ 全新点号（勾选=以 Excel 为准自动建点）：        │
   │   ☑ LZ-01 (沉降)  → 将自动创建为位移点(有X行) │
   │   ☐ LZ-02 …                                  │
   └────────────────────────────────────────────┘
Step3 确认后进入既有 valid/conflict/error 预览 → Step4 导入
```

- **类型推断**：全新点号自动建点时的类型 = 该点出现的数据分量——只有沉降列→`settlement`；只有位移 X/Y 列→`displacement`；两者都有→`both`；
- **初始值落库**：若为"初始点文件"（只有初始值列，判定为 V0 期，既有逻辑已支持），自动建的点 V0 = Excel 初始值；
- **后缀兜底**：同一 Excel 内疑似/全新点号超过 20 个时，提示"更建议在项目里先批量建点或改用测点批量新建"，避免自动建点把点号搞乱。

### 2.5 接口设计

```
POST /projects/{pid}/import/match-points
  body: {sheet_rows:[{point_no, series_type, component, is_v0_sheet}]}
  → {exact:[...], suggest:[{excel_no, candidate_point_no, confidence}], unknown:[{point_no, infer_type}]}

POST /projects/{pid}/import/batches/{id}/confirm   ← 扩展
  body 增加可选字段：
  { mappings: {"JJC-01":"JJC1", ...}, auto_create_points: [{"point_no":"LZ-01","point_type":"displacement"}] }
```

> 设计考量：自动建点是"用户显式勾选后才执行"，绝不静默建点（保持"数据库不依赖 Excel、导入不自动写结构"的原则底线，仅在初始点场景作为**用户主动选择的快捷通道**）。

## 三、观测报告导出模板选择

### 3.1 当前问题场景

- 现状：成果导出页只提供 2 个固定按钮（"导出 Excel 日报（按模板）" / "导出 Word 日报"），后端 `build_period_excel` 内置一套"竖向位移+水平位移"版式，**没有模板选择**；
- 痛点：
  1. 不同基坑/不同上报对象（业主/监理/内部）对报表版式、字段顺序、页眉页脚要求不同，目前只能导出一套版式后手工再改；
  2. 用户已有自己项目的标准 Excel 报送模板（如八号基坑文件），希望**直接以该文件为"底模"生成**，而不是系统重建近似版式（对应上次遗留的"模板特殊定位"需求）。

### 3.2 期望目标行为

- 导出页新增**模板选择器**：内置模板 + 项目自定义模板；
- 选定模板后，导出内容按其版式/字段/Sheet 结构生成（自定义模板支持**单元格定位规则**：哪些格填日期、点号、测值、变化量、速率、预警）；
- 模板可上传、可试导出、可删除；导出文件名带上模板名。

### 3.3 具体方案

#### (a) 模板库（两级）

| 层级 | 模板 | 说明 |
|---|---|---|
| 内置 | ① 标准监测日报（竖向位移 + 水平位移） | 现默认版式，保留为"标准模板" |
| 内置 | ② Word 观测日报 | 现有 Word 版 |
| 项目级 | ③ 用户上传模板 | 用户提供 Excel 作为底模（如八号基坑报送文件），上传到该项目，作为该项目导出选项 |
| 全局 | ④ 全局通用模板（可选 V1.2） | 跨项目复用（本期可不做，预留字段 is_global） |

**模板存储**：`templates/{project_id}/{name}/` 存原件副本 + 一个 `layout.json`（单元格定位规则）。模型：新建 `export_templates` 表（id/project_id(null=内置标记)/name/type(excel|word)/file_path/layout_json/created_at）。

#### (b) 模板选择入口（成果导出页）

```
成果导出
  ┌───────────────────────────────────────────┐
  │ 报告模板：  [标准监测日报 Excel ▾]          │
  │            ├ 标准监测日报（竖向位移+水平位移）│
  │            ├ Word 观测日报                  │
  │            └ 八号基坑报送版（本项目）◀新上传  │
  │ 期次： [2026-08-20 ▾]                      │
  │ [导出 Excel]  [导出 Word]                  │
  └───────────────────────────────────────────┘
  （模板旁：预览模板版式 / 上传新模板 / 删除模板）
```

#### (c) 模板上传与"特殊定位"配置

上传任一 Excel → 系统**自动解析其结构**（Sheet 列表 + 双层表头 + 数据起始行）并给出**可视化单元格映射编辑器**（延续用户"模板特殊定位"思路）：

```
模板单元格定位规则 layout.json（可自动识别 + 人工微调）：
{
  "sheets": {
    "竖向位移": {
      "data_start_row": 7,
      "point_col": 1,
      "fields": {
        "v0_m": 2, "prev_m": 3, "current_m": 4,
        "prev_cum_mm": 5, "cum_mm": 6, "delta_mm": 7,
        "rate": 8, "control_cum": 9, "control_rate": 10,
        "warning_level": 11
      }
    },
    "r.立柱结构水平位移": { "x_col_offset": 0, ... }   // 同点 X/Y 两行或两列均可配置
  },
  "meta": { "title_cell": "A1", "date_cell": "A3", "project_name_cell": "A2" },
  "mode": "per_row" | "x_y_two_rows" | "x_y_two_cols"
}
```

- **自动识别**：基于模板列头文本关键词（"点号/初始值/本次测值/累计/变化/速率/预警"）自动映射列 → 置信高直接填充；
- **人工修正**：映射编辑器里每个字段可从模板下拉选择对应列/单元格；
- 保存后即可作为该项目导出模板；导出 = 打开模板副本 → 按 layout 填入 → 另存为带期次的成果文件。

#### (d) 选型对导出内容/格式的影响

| 选择 | Sheet/结构 | 数据 | 格式 |
|---|---|---|---|
| 标准 Excel 模板 | 竖向位移 + 水平位移（2 Sheet） | 自动填全部字段+预警等级 | 系统版式（宋体/边框/合并，如现状） |
| 用户上传模板 | **按该模板原样**（保留封面/签字/页眉等所有 Sheet 与格式） | 只写 layout 配置的定位格，其余区域（签名、结论、页眉）原样保留 | 100% 模板外观 |
| Word 模板（内置） | 单文档：汇总表+预警清单+分析 | 同现状 | 现状版式 |
| Word 用户模板（V1.2） | 书签/占位符替换 | 预留 | — |

#### (e) 接口设计

```
POST   /templates/upload          (multipart: file + project_id + type + name) → 解析返回建议 layout
GET    /projects/{pid}/export-templates            → 内置 + 项目模板列表
PUT    /projects/{pid}/export-templates/{id}/layout  → 保存单元格定位
DELETE /projects/{pid}/export-templates/{id}
GET    /projects/{pid}/reports/excel?template_id={id}&obs_date=…   ← 关键：加 template_id 参数
```

> 向后兼容：不传 `template_id` = 用内置标准模板（现行为不变），老链路零破坏。

## 四、交付优先级建议

| 项 | 工作量预估 | 依赖 | 建议批次 |
|---|---|---|---|
| ① 批量新建测点（表格+文本粘贴两条主线，编号生成可后补） | 中 | 无 | **第一批（独立可用，立竿见影）** |
| ② 初始点导入匹配映射（规范化+P2 建议自动对应+自动建点勾选） | 中 | 需与导入九步流程衔接 | **第二批（紧接 ①，因为 ① 提供了另一出路）** |
| ③ 导出模板选择（先做"用户上传模板+自动识别 layout"主链路） | 大 | 需新增表 + 可视化映射编辑器 | **第三批（最长，建议先出自动识别不出的兜底=退回标准模板）** |

**验收口径**：
- ① 能用一段粘贴文本 30 秒建完 20 个测点，重复点被跳过并明示；
- ② 导入"点号写法不一致"的初始 Excel，可在预览页一键采纳映射后成功导入；全新点可勾选自动建点；
- ③ 上传八号基坑报送模板 → 选择它导出 → 打开文件核对与模板版式一致且数据正确。

## 附：与既有架构原则的一致性

- 三条均**只触碰"录入效率/导出呈现"层**，不改变原始数据模型、计算引擎、预警引擎、唯一约束；
- 批量建点沿用 UNIQUE(point_no in project)；自动建点仅在用户显式勾选时执行（不破坏"数据库不依赖 Excel"）；
- 新增唯一一张派生配置表 `export_templates`（模板配置属配置类，非观测数据），可随备份一起纳入 `database/backups`；
- 所有校验"先预览后落库"，与既有九步导入原则同源。
